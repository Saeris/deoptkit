## Direction options (for the maintainer to weigh)

- **Inlining-aware attribution (finding 9).** Port the semantics of V8's `processCodeSourceInfo` (BSD, add to THIRD_PARTY_NOTICES) so an IC or tick pc resolves to the inlined function and its real script. Payoff: no ghost findings in native mode, per-function heat without the file-level fallback, and line-level ticks for `get_function`. Cost: multi-day; needs new fixture assertions on inlined sites.
- **Map-details parsing (finding 10).** Parse the `map-details` block into `{ properties, stable, prototype }` at load, drop the raw text, and let churn findings list which properties differ across the sibling maps. Payoff: the churn explanation names the fix; memory per session falls. Cost: the "gnarly regexes" SPEC §3 warned about.
- **Self-dogfooding (finding 13).** A `bench/parse.bench.mjs` over `fixtures/logs` plus a `deoptkit ci` step in CI with committed baselines. Small, and the first real-world calibration data for the severity bands.
- **Claude Code plugin (finding 14).** Thin: `.claude-plugin/plugin.json`, `.mcp.json`, one skill. Keep it a projection over the server's `instructions`, never a second source of truth.

## Findings considered and rejected

- `CodeMap` uses array splice per insert (O(n) each): 11 MB fixture logs parse in 80–100 ms with 2,500 code entries. Revisit only if a real-application log parses in more than a few seconds.
- Checked-in fixture logs as repo bloat: `fixtures/logs/**` is gitignored (`*.log`); the repo pack is 2.2 MB. No action.
- `@vitest/coverage-v8` is unreferenced by scripts or config: harmless, keeps `vp test --coverage` available. Keep.
- Yarn peer warning "doesn't provide vite, requested by vitest": expected under the Vite+ catalog alias; cosmetic.
- Hand-rolled JSON-RPC in `src/lsp/jsonrpc.ts`: a recorded maintainer decision (API-compatible with vscode-languageserver for a later swap).
- Low-level `Server` instead of `McpServer`: the SDK's `registerTool` still accepts only zod schemas; Valibot stays. Plan 008 adds annotations and structured content without changing that.
- `profile_run` executes arbitrary commands: the tool's purpose; MCP hosts gate calls with user approval.
- `runWorkload` resolves `node` to `process.execPath`: documented choice; a `nodePath` option can follow if users report V8-version mismatches.
- MCP `resources` (`deopt://session/{id}/summary`): tools already cover it for agents.
